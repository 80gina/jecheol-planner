## 1. 분석 주제 및 선정 이유

### 무엇을 분석했나

평생학습센터 요리교실에서 실제로 쓰는 **식재료 9종의 2년치 일별 소매가격**을 분석했다.
여기에 **창원 지역 일별 기온**을 붙여, 가격 변동의 배경을 함께 살폈다.

### 왜 이 주제인가

요리교실을 운영할 때마다 되풀이되는 문제가 있다.
**한 달 전에 짠 식단표의 재료비가 수업 당일에 맞지 않는다.**
배추 한 포기가 3천 원이던 것이 6천 원이 되어 있으면, 12인 기준 수업의
재료비 계획이 통째로 어긋난다.

그래서 알고 싶었던 것은 하나다.
**"제철에 사면 싸다"는 말이 데이터로 사실인가, 그리고 얼마나 사실인가.**

이 질문은 검색으로는 답이 안 나온다. "배추는 겨울이 제철"이라는 정보는 흔하지만,
**"그래서 12월에는 6월보다 몇 % 더 내야 하는가"** 는 아무도 알려주지 않는다.
가격 데이터를 직접 봐야 나오는 숫자다.

### 기존 프로젝트와의 연결

이 분석은 별도 과제가 아니라, 진행 중이던 **제철밥상 플래너**(`jecheol-planner`)의
가격 수집 모듈을 시계열 분석용으로 확장한 것이다.
플래너의 목표가 "지금 싼 재료로 식단을 짜는 것"이므로,
"무엇이 언제 싼가"를 아는 것이 그 앞 단계에 해당한다.

### 3-3. 분석 대상 9품목과 선정 이유

품목은 **짝을 지어** 골랐다. 혼자 있는 숫자는 해석이 안 되기 때문이다.

| 짝 | 품목 | 확인하려는 것 |
|---|------|---------------|
| **정반대 짝** | 시금치 ↔ 오이 | 겨울 제철 vs 여름 제철 — 곡선이 거울처럼 뒤집히는가 |
| **같이 가는 짝** | 배추 ↔ 무 | 둘 다 김장 수요 — 같은 달에 같이 오르는가 |
| **닮은 짝** | 감자 ↔ 고구마 | 둘 다 저장 작물 — 저장이 계절성을 얼마나 눌러주는가 |
| **대조군** | 콩나물 | 실내 재배 — 계절성이 **없어야** 한다 |
| **공통 재료** | 대파 | 거의 모든 메뉴에 들어감 — 전 회차 원가에 영향 |
| **소액 재료** | 애호박 | 값은 작지만 12인 수업에서 누적됨 |

> **대조군을 넣은 이유가 중요하다.** "배추는 겨울에 비싸다"만 보여주면
> "원래 다 그런 것 아니냐"는 반문을 막을 수 없다.
> 계절성이 **없는** 품목을 나란히 놓아야 "다른 건 안 그런데 배추만 그렇다"가 성립한다.

## 5. 적용한 시계열 분석 기법

과제 요구는 2가지 이상이다. 5가지를 적용했다.

| # | 기법 | 왜 필요했나 | 어떻게 했나 |
|:-:|------|-------------|-------------|
| 1 | **이동평균** (7일·30일) | 일별 원본은 잔떨림이 심해 방향이 안 보인다 | 중심 아닌 후행 이동평균. 7일은 주 단위 요동을, 30일은 월 단위 흐름을 본다 |
| 2 | **변화율** (1일·30일) | 급등·급락이 **언제** 일어났는지 찾기 위해 | `pct_change()` |
| 3 | **월별 계절 지수** | 배추(원 단위 4천)와 애호박(1천5백)을 한 그림에 못 올린다 | 각 품목의 연평균을 100으로 놓고 월평균을 지수화 |
| 4 | **변동계수** (CV) | 표준편차만 보면 "비싼 품목이 많이 흔들린다"는 당연한 결론만 나온다 | 표준편차 ÷ 평균 × 100 |
| 5 | **시계열 분해** (보너스) | 물가 상승분과 계절 변동을 갈라 봐야 "실제로 얼마나 오른 것인가"가 나온다 | 고전적 가법 분해를 직접 구현 (아래 참조) |

### 시계열 분해를 직접 구현한 이유

`statsmodels.seasonal_decompose` 를 부르면 한 줄로 끝난다.
그러나 **"어떻게 분해했는가"에 답할 수 없게 된다.**
고전적 분해는 이동평균 세 번이면 되므로 직접 짰다. (`analyze.py` 의 `decompose()`)

```
1) 추세   : 1년치(영업일 261일) 중심 이동평균
            → 한 해를 통째로 평균 내면 계절 성분이 서로 상쇄되고 긴 흐름만 남는다
2) 계절성 : (원본 − 추세) 를 '몇 월 며칠인가'로 묶어 평균
            → 12월 31일과 1월 1일이 이어지도록 앞뒤로 한 바퀴씩 붙여 평활
3) 잔차   : 원본 − 추세 − 계절성. 설명되지 않고 남은 부분
```

> **가장자리를 비워 둔 이유**: 1년 창이 다 차지 않는 구간(양 끝 약 6개월)은
> 추세를 계산하지 않고 비워 두었다. 절반만 채워 계산하게 하면
> **없는 추세가 만들어져 보인다.** 모르는 구간은 비워 두는 편이 정직하다.

## 9. 한계점

정직하게 적는다. **한계를 아는 것이 분석의 일부다.**

| # | 한계 | 왜 문제인가 | 어떻게 보완할 수 있나 |
|:-:|------|-------------|----------------------|
| 1 | **관측 기간이 2년뿐** | 계절 패턴이 두 번만 반복되었다. "매년 그렇다"고 말하기엔 표본이 얇다 | 5년치로 늘리면 반복성을 주장할 수 있다 |
| 2 | **전국 평균 시세** | 요리교실은 창원에서 열리는데 가격은 전국 값이다. 지역 차가 반영되지 않았다 | 지역코드를 넣어 창원 시세로 다시 수집 |
| 3 | **상관 ≠ 인과** | 기온과 가격의 상관은 관계의 세기일 뿐이다. 김장 수요·유가·인건비 등 다른 요인은 넣지 않았다 | 뉴스 데이터(bapsang-trend)를 결합해 이벤트 시점을 대조 |
| 4 | **이상치 기준이 임의적** | ±50%는 내가 정한 값이다. 이 기준을 바꾸면 결과도 조금 달라진다 | 기준을 30%·70%로 바꿔 결과가 얼마나 흔들리는지 확인(민감도 분석) |
| 5 | **분해의 가장자리 결측** | 추세가 양 끝 6개월씩 비어 있다 | 기간을 늘리면 관심 구간이 가운데로 들어온다 |
| 6 | **품종·등급을 하나로 봄** | 같은 배추도 품종과 등급에 따라 값이 다른데 대표값 하나만 썼다 | 품종별로 나눠 수집 |

## 10. AI 사용 로그 (과제 필수 항목)

| # | 사용 작업 | 사용 이유 | 검증 방법 |
|:-:|-----------|-----------|-----------|
| 1 | **KAMIS·기상청 API 연동 코드 작성** | 두 API 모두 응답 형식이 문서와 다를 수 있어, 방어적으로 짜는 데 시간이 많이 든다 | `probe` 명령으로 실제 응답 구조를 눈으로 확인한 뒤 파서를 맞췄다. 품목 코드를 추측하지 않고 `codes` 명령으로 API에서 직접 받아 적었다 |
| 2 | **정제·분석·시각화 코드 작성** | pandas 시계열 처리와 matplotlib 세부 설정은 반복 작업이라 직접 짜면 오래 걸린다 | **정답을 미리 심은 가짜 데이터**로 검증했다. 배추에 "연 6% 상승"을 넣고 돌렸더니 분해 결과의 추세선이 우상향으로 나왔다. 정답을 아는 데이터에서 정답이 나왔으므로 계산이 맞다고 판단했다 |
| 3 | **시계열 분해 알고리즘** | 개념은 알지만 계절 성분의 연말연시 불연속 같은 세부는 놓치기 쉽다 | `statsmodels` 를 **쓰지 않고** 직접 구현했다. 라이브러리를 부르면 결과는 나오지만 원리를 설명할 수 없다. 3단계(추세→계절성→잔차)를 코드 주석에 남겼다 |
| 4 | **오류 원인 진단** | `metadata-generation-failed`, `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 등 메시지만으로는 원인을 알기 어렵다 | 각 오류를 고친 뒤 **다시 실행해 해결됐는지 확인**했다. 8장에 증상→원인→해결을 기록했다 |
| 5 | **리포트 문장 다듬기** | 관찰과 해석을 섞어 쓰지 않도록 표현을 정리 | 모든 수치를 `data/summary.json` 및 그래프와 **직접 대조**했다. 최종 해석과 결론은 내가 판단했다 |

### AI에게 맡기지 않은 것

| 항목 | 이유 |
|------|------|
| **분석 주제와 품목 선정** | 요리교실 운영에서 나온 실제 필요다. 남이 정해줄 수 없다 |
| **정제 기준 결정** | ±50%, 3일 등의 값은 데이터를 보고 내가 정했다 |
| **인사이트의 원인 가설** | 그래프에서 사실은 뽑아낼 수 있어도, 왜 그런지는 현장 감각이 필요하다 |
| **한계점 판단** | 무엇을 못 했는지는 만든 사람이 가장 잘 안다 |

## 11. 재현 방법

### 준비

```bash
git clone https://github.com/◻(GitHub 아이디)/jecheol-planner
cd jecheol-planner
pip install -r requirements.txt
```

### 인증키 설정

```bash
# .env.example 을 복사해 .env 로 만들고 두 키를 채운다
#   KAMIS_CERT_KEY / KAMIS_CERT_ID : https://www.kamis.or.kr → Open-API
#   KMA_SERVICE_KEY                : https://www.data.go.kr → ASOS 일자료 (Decoding 키)
```

### 실행 순서

```bash
python main.py basket            # 1. 분석 대상 확인 (키 불필요)
python main.py codes             # 2. 품목 코드를 KAMIS 에서 받아 저장
python main.py collect --years 2 # 3. 2년치 가격 수집 → data/prices_raw.csv
python main.py weather --years 2 # 4. 기온 수집 → data/weather_raw.csv
python main.py analyze           # 5. 정제·분석·그래프 → images/
```

| 항목 | 값 |
|------|-----|
| OS | Windows 11 |
| Python | ◻(`python --version` 결과) |
| 주요 라이브러리 | requests, python-dotenv, pandas, numpy, matplotlib |
