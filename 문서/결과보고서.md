# Ⅰ. 과제 개요

## 1. 무엇을 만들었나

요리교실 식재료 **9품목의 일별 소매가격 1년치**(2025-09-10 ~ 2026-09-10)를 수집·정제·분석하고,
**창원 지역 일별 기온**을 결합해 가격 변동의 배경을 살핀 시계열 분석 리포트.

산출물은 리포트(`REPORT.md`), 그래프 6장, 수집·분석 코드, GitHub 저장소다.

## 2. 왜 만들었나 — 과제 요건이 아닌 실제 동기

평생학습센터 요리교실을 운영하면서 되풀이된 문제가 있다.
**한 달 전에 짠 식단표의 재료비가 수업 당일에 맞지 않는다.**
배추 한 포기가 3천 원이던 것이 6천 원이 되면 12인 수업의 예산 계획이 통째로 어긋난다.

"제철에 사면 싸다"는 말은 누구나 한다. 그런데
**"그래서 12월에는 6월보다 몇 퍼센트 더 내야 하는가"** 는 검색으로 나오지 않는다.
가격 데이터를 직접 보아야만 나오는 숫자다. 그 숫자를 구하는 것이 이 과제의 목적이었다.

## 3. 기존 프로젝트와의 연결

새 프로젝트를 만들지 않고, 진행 중이던 **제철밥상 플래너**(`jecheol-planner`)를 확장했다.

| 이미 있던 것 | 이번에 더한 것 |
|--------------|----------------|
| `config.py` — 설정·키·로깅 | `basket.py` — 분석 대상 정의 |
| `kamis.py` — KAMIS 클라이언트 (하루치 조회) | `kamis.py` 에 기간 조회·코드 조회 추가 |

**왜 확장을 택했나**: 재시도·타임아웃·원문 보존 같은 까다로운 부분이 이미 들어 있었다.
새로 만들면 그걸 다시 짜야 한다. 그리고 "왜 이 주제인가"에 대한 답이 훨씬 단단해진다.

## 3. 의도적 결정 사항

| 결정 | 이유 |
|------|------|
| **`.gitignore` 에서 `data/` 를 풀었다** | 원래 `data/` 전체를 제외하고 있었다. 과제는 데이터를 저장소에 포함하라고 요구한다. `data/*.db` 와 `data/raw/` 만 남기고 CSV 는 올라가게 바꿨다 |
| **`.env` 는 계속 제외** | 인증키가 GitHub 에 공개되면 안 된다. `.env.example` 만 올려 어떤 키가 필요한지 알린다 |
| **`requirements.txt` 에 `==` 대신 `>=`** | 버전을 못 박았더니 그 버전에 맞는 설치 파일이 없어 소스 빌드로 넘어갔고 실패했다. XI장 오류 2 참조 |
| **품목 코드를 코드에 적지 않음** | 외워서 적으면 틀린다. `codes` 명령으로 API 에서 직접 받아 `data/item_codes.json` 에 저장한 뒤 그 파일을 보고 수집한다 |

## 2. 구간 분할 이유

작업을 7구간으로 나눴다: 준비 → 수집 코드 → 실제 수집 → 정제·분석 → 리포트 → 보너스 → 제출.

**왜 나눴나**: 인증키 발급이 외부에 달려 있어 언제 될지 알 수 없었다.
키가 필요한 작업(수집)과 필요 없는 작업(코드 작성·정제 로직)을 갈라놓으면
**기다리는 동안에도 진도가 나간다.** 실제로 KAMIS 키를 기다리는 동안
분석 코드와 시각화를 전부 완성했다.

## 3. 반복 작업 패턴

```
코드 작성 → 실행 → 결과 확인 → 스크린샷 → git add → git commit
```

이 순서를 매 단계 반복했다. 커밋을 한 번에 몰지 않은 이유는
**되돌아갈 지점을 만들기 위해서**다. 수집 코드를 고치다 꼬였을 때
"분석 코드 넣기 직전"으로 돌아갈 수 있어야 했다.

### ✅ 확인됨

**확인 절차**: `REPORT.md` 2장에 질문 5개를 표로 정의했다.

**결과**: 과제 요구는 3개 이상. 5개를 정의했다.
그 중 Q1·Q4는 그래프로 바로 답이 나오고, Q2·Q3은 해석이 필요하며, Q5는 실무 적용이다.
과제가 "그래프로 확인 가능한 것과 추가 해석이 필요한 것이 섞여도 된다"고 했으므로
의도적으로 섞었다.

**증빙**: `REPORT.md` 2장

### 왜 그렇게 했는가

질문을 먼저 정하고 데이터를 봤다. 반대로 하면 **눈에 띄는 것만 보게 된다.**
데이터를 먼저 보면 "어, 여기 튀네" 하는 지점만 쫓게 되고,
그건 분석이 아니라 우연을 줍는 일이다.

특히 **Q5를 넣은 것이 중요하다.** 앞의 네 질문은 "알고 싶다"이지만
Q5는 "그래서 무엇을 할 것인가"다. 이게 없으면 분석이 보고서에서 끝난다.

1년 중 120일 가까이 비었다면 심각한 데이터다 — 그런데 그게 **전부 토·일요일**이었다.

KAMIS 는 주말에 시세 조사를 하지 않는다. 없는 게 정상이다.
그걸 결측으로 세고 보간하면 **한 번도 열리지 않은 시장의 가격을 만들어내는 것**이 된다.
영업일 달력(`freq="B"`)으로 바꾸자 결측이 **품목당 18일**로 줄었고, 9품목이 모두 같은 값이었다.
특정 품목의 조사 누락이 아니라 **공휴일**이라는 뜻이다. 품목마다 제각각이었다면
수집 쪽을 의심해야 했다.

**② 평균이 아니라 중앙값을 쓴 이유.**

이상치를 잡으려고 "평균에서 많이 벗어난 값"을 찾으면 잡히지 않는다.
평균 자체가 그 튄 값 때문에 끌려가 있기 때문이다.
중앙값은 순서상 가운데 값이라 극단값 하나에 흔들리지 않는다.

**③ ±50%가 임의적이라는 것을 인정한다.**

이 값은 내가 정했다. 30%로 하면 정상적인 김장철 급등도 이상치로 잘려나가고,
100%로 하면 명백한 오타를 놓친다. 데이터를 보고 타협한 값이며,
리포트 9장 한계점에 **"기준을 바꾸면 결과도 달라진다"** 고 명시했다.

| **이상치 처리** | 31일 이동중앙값 ±50% 밖 → 제거 후 보간 대상으로 |

# Ⅵ. 그래프에서 확인한 사실(관찰)과 해석(가설)을 구분해 설명할 수 있다

### 📋 한눈에 보기

| | 관찰 (Fact) | 해석 (Hypothesis) |
|---|---|---|
| **무엇** | 그림에서 눈으로 읽히는 것 | 왜 그런지에 대한 추측 |
| **표현** | "12월 지수 141, 6월 58" | "김장 수요가 겹쳤을 가능성이 있다" |
| **검증** | 다시 그리면 같은 값이 나온다 | 다른 데이터가 있어야 확인된다 |
| **리포트 위치** | 각 그림 아래 "관찰" | 7장 인사이트의 "원인(Why)" |

### ✅ 확인됨

**확인 절차**: `REPORT.md` 7장의 인사이트를 **관찰 / 원인 / 행동** 3칸 표로 강제했다.
칸이 나뉘어 있으면 섞어 쓸 수가 없다.

**결과**: 인사이트 **5개**를 작성했으며(요구 3개 이상), 모든 관찰에 **숫자와 그림 번호**가 들어 있다.

**증빙**: `REPORT.md` 7장

### 왜 그렇게 했는가

**가장 위험한 문장은 "12월에 비싼 이유는 김장 때문이다" 다.**
이 문장은 관찰처럼 들리지만 해석이다. 그리고 검증되지 않았다.

내 데이터로 말할 수 있는 것은 **"12월 지수가 141이다"** 까지다.
그 이유가 김장인지, 저온인지, 유가인지는 이 데이터에 들어 있지 않다.

그래서 기온 데이터를 붙였다. 하지만 그것도 상관까지만 말해준다.
**그림 6의 콩나물이 그 증거다.** 상관계수가 +0.94로 가장 높은데 선은 거의 평평하다.
지수가 95에서 105 사이, 즉 ±5% 안에서만 움직인다.
**상관이 높다는 것과 영향이 크다는 것은 다른 말이다.**

이 사례를 리포트와 시연에 일부러 넣었다. 상관계수를 신뢰하지 않는 근거로 쓰기 위해서다.

| **관찰의 조건** | 숫자 + 그림 번호가 반드시 포함 |
| **해석의 표현** | "~로 보인다", "~일 가능성이 있다" |

# Ⅶ. 시계열의 트렌드·계절성·노이즈 개념을 설명할 수 있다

### 📋 한눈에 보기

| 성분 | 무엇인가 | 이 데이터에서는 | 어떻게 구했나 |
|------|----------|-----------------|---------------|
| **추세 (Trend)** | 주기를 걷어내고 남는 긴 흐름 | 배추 6,722 → 6,129원 (−8.8%) | 주기 길이만 한 중심 이동평균 |
| **주기 (Seasonality)** | 같은 위상에서 반복되는 모양 | 요일 효과: 금요일 +19.8원, 월요일 −12.5원 | (원본 − 추세)를 위상별로 평균 |
| **노이즈 (Residual)** | 설명되지 않고 남는 잔떨림 | 표준편차 99.2원 — 주기 성분(32.3원)보다 크다 | 원본 − 추세 − 주기 |

> **연간 주기가 아니라 주간 주기로 분해했다.** 자료가 1년(261영업일)뿐이라
> 261일 창을 두 번 이상 채울 수 없어 연간 분해는 추세가 통째로 빈다.
> 연간 계절성은 **월별 계절 지수**(그림 3)로 따로 다루되, 1주기만 관측되었으므로
> "매년 반복된다"가 아니라 **"관측된 한 해의 모양"** 으로만 읽는다. 리포트 5-2 참조.

### ✅ 확인됨

**확인 명령**:

```powershell
python main.py analyze --focus baechu
```

**결과**: `images/05_decompose.png` 에 4단 그래프가 생성된다.
`data/summary.json` 의 `분해` 항목에 추세 시작·끝값, 계절 진폭, 잔차 표준편차가 저장된다.

**증빙**: `images/05_decompose.png`, `data/summary.json`

### 왜 그렇게 했는가

**① `statsmodels` 를 쓰지 않았다.**

`seasonal_decompose()` 를 부르면 한 줄로 끝난다. 그런데 이 과제의 목표가
**"트렌드·계절성·노이즈 개념을 설명할 수 있다"** 이다.
라이브러리를 부르면 결과는 나오지만 **어떻게 분해했느냐에 답할 수 없게 된다.**

고전적 가법 분해는 이동평균 세 번이면 되는 계산이라 직접 짰다.
의존성이 하나 줄어드는 것은 덤이다.

```
1) 추세   : 1년치(261 영업일) 중심 이동평균
            → 한 해를 통째로 평균 내면 계절 성분이 상쇄되고 긴 흐름만 남는다
2) 계절성 : (원본 − 추세) 를 '몇 월 며칠인가'로 묶어 평균
3) 잔차   : 원본 − 추세 − 계절성
```

**② 12월 31일과 1월 1일을 이어붙였다.**

계절 성분을 날짜별로 평균 낸 뒤 평활할 때, 그냥 하면 **연말연시에 턱이 생긴다.**
12월 31일 다음이 1월 1일인데 데이터 순서상으로는 끝과 시작이라 이어지지 않기 때문이다.
앞뒤로 한 바퀴씩 복사해 붙인 뒤 평활하고 가운데만 잘라 썼다.

**③ 양 끝을 비웠다.**

1년 창이 다 차지 않는 구간(양 끝 약 6개월)은 추세를 계산하지 않고 비웠다.
`min_periods` 를 창의 절반으로 두면 그 구간도 값이 나오지만,
**그건 반쪽짜리 평균이라 없는 추세가 만들어져 보인다.**
처음 구현했을 때 실제로 양 끝이 급격히 꺾이는 그래프가 나왔고, 그게 계산 착시였다.
모르는 구간은 비워 두는 편이 정직하다고 판단했다.

### 📋 요약 표

| 구분 | 내용 |
|------|------|
| **분해 방식** | 고전적 가법 분해 (원본 = 추세 + 계절성 + 잔차) |
| **직접 구현한 이유** | 라이브러리를 쓰면 "어떻게"에 답할 수 없다 |
| **세부 처리 ①** | 연말연시 불연속 → 앞뒤로 한 바퀴씩 붙여 평활 |
| **세부 처리 ②** | 양 끝 결측 유지 → 반쪽 창은 없는 추세를 만든다 |
| **탈락 후보** | `statsmodels.seasonal_decompose` — 결과보다 설명 가능성을 택함 |

# Ⅷ. 이동평균·변화율 등 기본 기법을 왜/어떻게 적용했는지 설명할 수 있다

### 📋 한눈에 보기

| # | 기법 | 왜 (문제) | 어떻게 (해결) |

| 2 | 변화율 1·30일 | 급등락이 **언제**인지 찾아야 함 | `pct_change()` |
| 3 | 월별 계절 지수 | 단위가 다른 품목을 겹쳐 그릴 수 없음 | 연평균=100 으로 지수화 |
| 4 | 변동계수 | 표준편차만 보면 비싼 품목이 유리 | 표준편차 ÷ 평균 |
| 5 | 시계열 분해 | 물가 상승과 계절 변동이 섞여 있음 | Ⅶ장 참조 |

### ✅ 확인됨

**확인 명령**: `python main.py analyze`

**결과**: `data/prices_clean.csv` 에 `ma7`, `ma30`, `chg_1d`, `chg_30d` 컬럼이 추가된다.
그래프 6장이 `images/` 에 생성된다.

**증빙**: `images/02_moving_average.png`, `images/03_seasonality.png`, `images/04_volatility.png`

### 왜 그렇게 했는가

**① 이동평균을 왜 두 개 그렸나.**

하나만 그리면 "부드러워졌다"로 끝난다. 두 개를 겹치면 **둘이 갈라지는 지점**이 보인다.
7일선이 30일선을 뚫고 올라가면 최근 일주일이 지난 한 달 평균보다 비싸다는 뜻,
즉 오름세로 방향이 바뀌는 신호다. 장보기 시점을 정하는 데 쓸 수 있는 정보다.

**② 계절 지수를 왜 만들었나 — 이게 가장 실용적인 판단이었다.**

배추는 4천 원대, 애호박은 1천5백 원대다. 원 단위로 한 그림에 올리면
애호박은 바닥에 붙어 아무 변화도 안 보인다.
각 품목의 연평균을 100으로 놓으면 **"평소보다 몇 % 비싼 달인가"** 로 단위가 통일된다.
품목 간 비교가 그제서야 가능해진다.

**③ 표준편차를 그대로 쓰지 않은 이유.**

표준편차만 보면 값이 큰 품목이 자동으로 위에 온다. "비싼 게 많이 흔들린다"는
당연한 결론이라 정보가 없다. 평균으로 나눈 변동계수라야
**"자기 평균 대비 얼마나 흔들리는가"** 가 되어 값의 크기와 무관하게 비교된다.

**④ 집계 단위를 일별로 유지한 이유.**

월별로 뭉치면 그래프가 훨씬 깔끔해진다. 그러나 요리교실 장보기는
**특정 날짜 하루**에 이루어진다. 월평균으로는 "그 날 얼마였나"를 알 수 없다.
깔끔함 대신 실용성을 택했고, 대신 잔떨림 문제는 이동평균으로 해결했다.

# Ⅸ. 분석 목적에 맞는 질문을 AI에게 던지고, 생성된 코드·해석을 검증할 수 있다

### 📋 한눈에 보기

| 검증 대상 | 검증 방법 | 결과 |
|-----------|-----------|------|
| API 응답 파싱 코드 | `probe` 로 실제 응답 구조 확인 후 파서 작성 | 추측 없이 맞춤 |
| 품목 코드 | `codes` 로 API 에서 직접 수신 | 하드코딩 회피 |
| 분해 알고리즘 | **정답을 심은 가짜 데이터**로 검증 | 심은 값이 그대로 나옴 |
| 결측·이상치 처리 | 가짜 데이터에 결측·이상치를 일부러 섞어 시험 | 정상 처리 |
| 그래프 | 렌더링 후 눈으로 확인, 라벨 겹침 수정 | 3회 수정 |

### ✅ 확인됨

**핵심 검증 절차 — 정답을 심은 데이터로 시험하기**

인증키를 기다리는 동안 실제 데이터가 없었다. 그래서 **가짜 데이터를 직접 만들었다.**
단순한 난수가 아니라 **답을 미리 정해 심었다.**

| 품목 | 심은 값 |
|------|---------|
| 배추 | 계절 진폭 38%, 최고 12월, **추세 연 +6%**, 노이즈 7% |
| 콩나물 | 계절 진폭 **5%** (대조군) |
| 시금치 | 계절 진폭 45%, 최고 1월 |
| 오이 | 계절 진폭 40%, 최고 12월 |

여기에 3% 확률로 이상치(2.6배 또는 0.35배)와 2% 확률로 결측을 섞었다.

**결과**:

| 검증 항목 | 심은 값 | 분석 결과 | 판정 |
|-----------|---------|-----------|:----:|
| 배추 추세 방향 | 연 +6% 상승 | 분해의 추세선이 우상향 직선 | ✅ |
| 콩나물 계절성 | 거의 없음 | 변동계수 4.9%로 **최하위** | ✅ |
| 시금치 계절성 | 가장 큼 | 변동계수 32.7%로 **최상위** | ✅ |
| 이상치 검출 | 품목당 3% 삽입 | 품목당 0~4건 검출 | ✅ |
| 데이터 규모 | — | 품목당 약 500행 (요구 100행 초과) | ✅ |

**정답을 아는 데이터를 넣었더니 그 정답이 나왔다.**
이것이 계산이 맞다고 판단한 근거다.

**증빙**: 검증용 그래프 3장 (`샘플/` 폴더), 터미널 출력

### 왜 그렇게 했는가

AI가 만든 코드는 **문법 오류 없이 잘 도는데 답이 틀릴 수 있다.**
실행이 됐다는 것은 검증이 아니다.

특히 시계열 분해처럼 결과가 그럴듯해 보이는 계산은 위험하다.
그래프가 예쁘게 나오면 맞는 것 같지만, 부호 하나가 뒤집혀 있어도 그럴듯해 보인다.

그래서 **답을 아는 문제를 먼저 풀렸다.** 이건 실제 데이터가 없을 때만 쓰는
임시방편이 아니라, 데이터가 있어도 해야 하는 절차라고 생각한다.

### 실제로 잡아낸 것

이 검증 과정에서 **두 가지 오류를 잡았다.**

| 발견 | 증상 | 수정 |
|------|------|------|
| 가장자리 왜곡 | 추세선 양 끝이 급격히 꺾임 — 심은 값은 직선 상승인데 | `min_periods` 를 창 크기와 같게 변경 |
| 연말연시 불연속 | 계절성 곡선이 9월 부근에서 튐 | 앞뒤로 한 바퀴씩 붙여 평활 후 가운데만 사용 |

**가짜 데이터로 시험하지 않았으면 둘 다 놓쳤을 것이다.**
실제 데이터였다면 "원래 그런가 보다" 하고 넘어갔을 모양이었다.

### 왜 그렇게 했는가 — 내가 판단한 것들

**① 분석 주제와 품목 선정**

요리교실 운영에서 나온 실제 문제다. 그리고 품목을 **짝지어 고른 것**이 설계의 핵심이다.
정반대 짝(시금치↔오이), 같이 가는 짝(배추↔무), 닮은 짝(감자↔고구마), 그리고 대조군(콩나물).

**대조군을 넣기로 한 판단이 이 분석에서 가장 중요했다.**
"배추는 겨울에 비싸다"만 보여주면 "원래 다 그런 것 아니냐"는 반문에 답할 수 없다.
계절성이 **없는** 품목을 나란히 놓아야 비로소 "다른 건 안 그런데 배추만 그렇다"가 성립한다.
이건 통계 기법이 아니라 **논증 설계**이고, 코드가 알려주지 않는다.

**② 정제 기준**

±50%, 3일, 31일 — 모두 내가 정한 값이다.
데이터를 보고, 김장철 정상 급등이 잘려나가지 않는 선에서 타협했다.
그리고 **임의값이라는 것을 리포트에 명시했다.** 숨기면 물었을 때 무너진다.

**③ 라이브러리를 쓰지 않기로 한 결정**

`statsmodels` 를 쓰면 코드가 짧아지고 결과도 나온다.
그런데 과제 목표가 "개념을 설명할 수 있다"이므로, **설명 가능성을 택했다.**
이건 기술적 선택이 아니라 학습 목표에 대한 판단이다.

**④ 무엇을 못 했는지에 대한 판단**

한계점 6가지는 내가 작성했다. 무엇을 안 했는지는 만든 사람이 가장 잘 안다.
특히 "이상치 기준의 민감도 분석을 하지 않았다"는 아무도 지적하지 않으면 드러나지 않는 약점이다.

## 2. 아쉬운 점

| # | 내용 |
|:-:|------|
| 1 | **이상치 기준의 민감도 분석을 못 했다.** ±50%가 결과를 얼마나 좌우하는지 확인하지 못했다 |
| 2 | **전국 평균 시세를 썼다.** 요리교실은 창원에서 열린다 |
| 3 | **1년 표본은 얇다.** 계절 패턴이 **한 번만** 관측됐다. KAMIS 가 최근 1년만 제공해 지금 늘릴 방법이 없다 |
| 4 | **뉴스 데이터를 결합하지 못했다.** `bapsang-trend` 의 DB 가 옆에 있는데 이번에는 쓰지 못했다 |

## 3. 개선 방향

| 우선순위 | 개선안 | 기대 효과 |
|:---:|--------|-----------|
| 1 | 이상치 기준을 30/50/70%로 바꿔 결과 비교 | 기준의 임의성이 결론에 미치는 영향을 수치로 제시 |
| 2 | 창원 지역코드로 재수집 | 실무 적용도가 올라간다 |
| 3 | 매년 같은 시기에 수집해 쌓기 | KAMIS 가 1년만 제공하므로 한 번에 늘릴 수 없다. 2년치가 모이면 `pick_period()` 가 자동으로 연간 분해로 전환된다 |
| 4 | `bapsang-trend` 뉴스 DB 결합 | 급등 시점에 어떤 기사가 있었는지 대조 — 원인 가설의 근거 |

## 4. 배운 것

**그래프를 그리는 것과 읽는 것은 다른 일이다.**

코드는 하루면 짤 수 있었다. 그런데 "이 곡선이 무슨 뜻인가"를 정리하는 데
그보다 오래 걸렸고, 그 답은 어떤 라이브러리도 알려주지 않았다.

특히 **관찰과 해석을 갈라 쓰는 것이 생각보다 어려웠다.**
"12월에 비싼 이유는 김장 때문이다"라는 문장이 얼마나 자연스럽게 나오는지,
그리고 그게 사실이 아니라 추측이라는 것을 매번 의식해야 한다는 것을 알았다.

그리고 **상관계수를 믿지 않게 되었다.** 양파는 r=−0.79로 9품목 중 가장 강한데
계절 진폭은 32.6p 로 하위권이고, 배추는 진폭이 61.1p 로 두 배인데 r=−0.04 다.
**r은 관계의 방향이 얼마나 일정한가이지, 값이 얼마나 크게 움직이는가가 아니다.**
이 둘을 섞으면 "상관이 높으니 변동도 크다"는 틀린 문장이 나온다.
